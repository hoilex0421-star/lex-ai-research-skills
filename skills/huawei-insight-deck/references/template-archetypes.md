# Content structures inside the official body

Choose by the relationship the reader needs to understand. These research
structures are not extra Huawei masters. Keep official title/body/footer regions.

For a wider visual vocabulary, browse [all 42 page types](layout-atlas.md).
Each type has its own representative slide; use photo, chart, timeline, map,
comparison and mechanism structures to avoid repeating simple cards.

| Structure | Best question | Native content | Density decision |
| --- | --- | --- | --- |
| Architecture | What changes in the system? | Layers, modules, explicit data/control paths | 3–5 layers; split mechanism detail |
| Process/flow | How does it run? | Nodes and arrows; inputs, computation, output, feedback | 3–5 main stages; avoid crossing arrows |
| Route comparison | What differs under the same conditions? | Native table with stable row fields | 2–3 routes; split rather than shrink |
| Evidence + inference | What supports the claim and where does it stop? | Source figure/table at left, bounded inference at right | One central evidence item, visible qualifier |
| Timeline/evolution | What changed and what is hypothetical? | Editable events/dates, separate branches | No forced progression from alternatives |
| Case/mechanism | How does a representative example work? | Source figure, mechanism, measured scope | One clear case over many logos |
| Bottleneck → opportunity | What load creates an optimization need? | Mechanism → variable → resource → experiment | Label hypothesis until measured |
| Validation/roadmap | What can both parties deliver and verify? | Work, owners, milestones, acceptance table | No invented commitments |

The builder implements architecture, flow, comparison, evidence and validation.
For other structures, arrange native objects on the same canvas and use the assembler.
Use native charts when source data exist, with units, baseline and data lineage.
Do not create decorative fake charts.
